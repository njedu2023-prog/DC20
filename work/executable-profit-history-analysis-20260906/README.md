# 独立历史来源复核

该工具只验证来源，不训练模型，不改变每日名单或影子账本。
运行时必须从已完成 GitHub 日志取得 artifact manifest SHA，并独立指定 run ID、
run SHA 与 attempt，不能以压缩包内部身份作为自己的信任依据。

核验包括：全部文件哈希及路径、固定候选和严格日期范围、原始响应与分页完整性、
原始响应到 CSV 的一致性、同日已提交来源的重叠比较，以及明确的缺行/缺字段记录。
新空值不使用旧数据填补，也不转换为 0；来源可以采集完成而候选数值仍不完整。
来源通过只允许后续独立标签重建，`training_authorized` 始终为 false。

输出仅为本目录的新 `outputs/audit.json`，拒绝覆盖已有报告。
旧失败 artifact 应按对应的固定代码和请求单独核验，不能冒充本轮完整来源。

## 下载接收与诊断顺序

1. 从已完成的 Actions 运行取得压缩包 SHA-256 和日志中的 manifest SHA-256。
2. `receive_artifact.py` 使用这两个外部摘要验证本地 ZIP，并向仓库之外的新空物理
   目录独占解压。路径、文件集合、字节数、内容哈希或 CRC 不符即拒绝接收。
   接收成功只代表完整性，不能替代来源审计或允许训练。
3. 对接收目录运行 `audit_artifact.py`，另外固定该次 run ID、完整提交 SHA 和 attempt。
4. 单次完整来源需独立来源报告允许重建标签，才可进入单来源研究入口；本轮原始
   run 未完成，不能使用这个途径。其完整 1833 分区与独立补采的 19 个缺失分区，
   必须由相邻 `executable-profit-history-closure-20260906` 新包重新核验后才能组合。
   原失败状态及本目录 `outputs/audit.json` 的三条问题永久保留。完整 D、训练样本数
   和标签成熟时间门槛仍必须全部通过。

在 macOS 上使用 `/private/tmp` 等物理绝对路径，不使用 `/tmp` 符号链接。
失败包可以保存作故障证据，但接收工具不会将它变成有效训练来源。

## 特征与时序辅助诊断

`audit_features.py` 检查 48 个冻结特征的逐值来源一致性，并单独复算其中 10 个
历史晋级先验，执行当前及未来标签扰动检查。它不是对全部 48 列的完整因果证明，
也不证明历史行情在原始 D 日的修订状态、实际成交或未来盈利。
两个运行环境的报告除运行库版本外一致；原 20/60 日先验按有事件的日期滚动，
并非补齐全部 SSE 交易日，本轮不事后更改这个冻结定义。

`test_temporal_boundary.py` 使用明确标记的 450 个合成 D、5 折测试：未来标签及
48 个特征的扰动不能改变训练输入，且成熟日等于 cutoff 时整个 D 仍被排除。
这些合成样本只用于软件测试，没有拟合模型，也不进入任何市场收益统计。

`test_receive_artifact.py` 覆盖 29 项安全接收边界。所有测试均为离线，不调用行情
接口，不修改线上名单、模型权重或 Shadow 账本。
