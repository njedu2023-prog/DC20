# 一分钟执行延迟检查（独立研究，不改正式规则）

## 检查目的

在同一份冻结候选、同一买入价和同一次卖出决定下，比较：

- 基准：现有 10:00 / 已观察到封板后首次炸板的规则，下一分钟开盘价代理退出。
- 固定压力条件：原卖出决定形成后，至少等待 60 秒，才可使用随后符合条件的分钟开盘价代理退出。

不是寻找最优卖出时间，也不是把正式卖出规则改成 10:01。两组结果都保留；没有选择收益更高的一组、搜索参数或据此训练模型的入口。

按现有 **尚未获供应商确认的 BAR_END 假设**，10:00 决定的基准价格来自标签为 10:01 的分钟 open（该分钟从 10:00 开始）；延迟组最早采用标签 10:02 的 open（该分钟从 10:01 开始）。午休或隔夜已经超过 60 秒时，不再人为跳过恢复交易后的第一根可用分钟。

此检查不验证 BAR_START 解释，也不能证明 BAR_END 正确。若供应商标签实际表示分钟开始，固定时钟 10:00 能使用哪些已完成价格属于另一项尚未解决的来源问题。

## 不变的边界

- 冻结晋级名次、D 名单、入场证据、费用及原卖出决定不变。
- 已形成卖出决定后重新封板，不撤销决定。
- 正常 10:00 退出之外，保留原内核可能在 10:00 前观察到封板后炸板的行为。
- 完整分钟、交易日历、日线、涨跌停限制与价格连续性验证仍适用。
- 分钟成交量只能提供事后流动性代理，不能证明该分钟开盘处的真实订单成交或容量。
- 45bp 和 90bp 各扣一次；负收益、延迟后改善或恶化、卖不出与缺证据都保留。
- 未解决记录不计零、不伪装成未成交。明确未成交记录才保留原槽位零收益。
- 不推导账户净值，不覆盖影子账本，不发布页面，不替换模型，不接触 2026-09-14 起的前瞻留出期。

## 工具

`exit_latency.py` 是独立回放比较内核，读取并核对原退出内核 SHA；不改变原内核。回调负责证据读取，模块检查两组使用的证据快照一致性。

`latency_report.py` 是只读报告入口：

1. 使用 `acceptance.py` 验收明确指定的 ZIP、运行编号及源码提交。
2. 对照 ZIP 校验独立解包镜像中的全部原始文件。
3. 从原历史源重建冻结 D 特征及基准标签，要求与归档完全一致，不拿旧收益当价格真值。
4. 对全部候选保留记录，对已结算基准逐行做固定延迟比较。缺少延迟退出需要的后续证据时保持未解决。
5. 汇总整体及冻结晋级 Top1 / Top2 / Top3 的敏感性。均值只针对两组均已结算的明确子集，同时展示全部候选、未成交、未解决和完整 D 数量，不能当完整策略收益。
6. 再次核对所有归档文件未被改动。仅向标准输出返回 JSON，不修改镜像或既有研究输出。

命令（实际产物到齐且独立核验后）：

```sh
python work/profit_1000_upgrade/latency_report.py \
  --root VERIFIED_EXTRACTED_V2_MIRROR \
  --archive ACTUAL_V2_ARTIFACT.zip \
  --expected-zip-sha256 ACTUAL_VERIFIED_SHA256 \
  --expected-run-id 34676871475 \
  --expected-commit df6c38806da20066f673875a4a83c37fa895d2e4
```

工具测试中的合成行情只是软件测试，不是历史回测结果。只有真实归档验收及回放实际完成后，才可报告真实样本的延迟敏感性；即便压力条件下为正，也不等于未来盈利或具备正式上线条件。
