# 停牌证据与模型版本分离

## 生效与兼容

D20261111 起，P0 在固定的源 main HEAD 中读取 `data/market/suspension_evidence/index.json`，并将索引、所引用的全部版本、逐股记录及公告 PDF 的 SHA-256 / Git blob / mode 绑定进 receipt。候选导入、原始 P0 base tree、冻结 ZIP、发布观察和观察归档都复核这一闭包。后续提交里出现的文件不能补作原始运行已拥有的证据。

D20261110 及更早记录仍使用原始 receipt 形状；不增加新字段、不重写历史冻结。`data/market/confirmed_suspensions.json` 的原有三条事实和模型 pin 保留。新事实只进入独立注册表，不需要修改模型 artifact、权重或固定模型清单的数据 pin。新增校验代码本身仍受代码 pin 约束。

## 新事实要求

每个记录对应股票代码和明确的停牌、复牌日期，必须提供批准的官方披露域名、发布日期、已存档的 PDF 字节与散列。官方域名字符串本身不是真实性证明：源 Git HEAD 中的新增事实须经过公告内容人工核对，确认公告确实支持该股票与日期。运行时校验公告字节和固定源版本，继续校验无交易记录的停牌段、边界价格、严格交易日历及原有特征计算规则；不根据缺失行情自行猜测停牌。

新增证据版本是内容寻址对象。重复、重叠、非法路径、坏 hash、缺失 PDF、不受信任域名，以及在当前 D 不可知的披露均不可用。完整未来记录可以存在于仓库，但复牌晚于 D 的记录不用于该 D；它的字节损坏也不能被忽略。索引损坏/缺失不能当作空表继续输出。

## 受控追加与回退边界

目前未新增自动写入器。新增停牌事实时，提交者必须读取远端 main SHA 和 index 原字节，保留全部既有内容寻址对象，只追加一个新版本，调用 `validate_append_transition` 校验：前序 index SHA 与预期相同，新版本直接引用旧版本、序号递增、旧对象保持逐字节绑定，然后使用同一 main HEAD 的 Git compare-and-swap 提交。CAS 失败重新核验，不 force。

单独的内容哈希链不能阻止拥有仓库写权限的人绕过受控入口、手工将 index 改回合法旧版本。这个边界不得描述成“任意回退都会被运行时自动识别”。首次上线只增加空 genesis，没有新增或改写历史停牌事实。

## 有界容量

当前最多 128 个版本、512 个闭包文件、总计 16 MiB，单对象不超过 4 MiB。取源、receipt、ZIP、发布观察和证据写入预算跟随已验证闭包增加，历史 D 保持原有语义。测试覆盖 40 次合法追加经过登记、完整源清单核验、投影与冻结源归档，不再在第 33 次追加触发旧容量边界。

达到容量前需要受审查的 checkpoint 格式迁移；不得临时删除历史对象、忽略注册源或无限扩大读取范围。容量限制属于明确的完整性边界，不能承诺永远不会再阻断。已实现的逐股隔离适用于固定 Ridge 的单股历史不足、缺 D 观测等情形。停牌事实或共享版本不可核验时，不能简单排除该股再宣称完整正式榜单；影响 P0 整池及整体排名者仍阻止本次正式生成，并提供明确的受影响范围。
